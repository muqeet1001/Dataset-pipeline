pipeline/runner.py: sequential processing, locks, checkpoints, immutable handoffs,
pending delivery state and consumer receipt validation.
pipeline/clothing.py: catalog/config parsing, seeded sex-matched garment selection,

pipeline/vstitcher_job.py: standalone native BwApi script for VStitcher-CLI.
tests/test_clothing.py and tests/test_runner.py: relevant existing tests.

The native script currently checks input hashes, opens a copied garment, verifies
the native size ID/name, selects that size, imports/selects the MHR avatar, calls
GarmentPrepare, requests synchronous uncached GarmentDressEx iterations, calls
GarmentFinish, checks current avatar/size, saves dressed.bw, and calls
RenderExport3DObject for scene.glb and garment.glb. It closes the working garment.
It can optionally use a compatible one-avatar reference VSA via AvatarImportVSA
and AvatarImportEx. Do not assume any call's current signature, licensing, unit
handling, defaults or behavior works until tested against the installed runtime.
Audit and fix the script using the official docs and native results.

The CLI subprocess receives the job file through the environment variable
DATASET_PIPELINE_VSTITCHER_JOB and runs --script pipeline/vstitcher_job.py.
Each attempt has a fresh directory plus stdout/stderr and native-result.json.
The expected per-variant outputs are dressed.bw, scene.glb (body and garment),
and garment.glb (garment only), with SHA-256 receipts and source linkage.

Current native success is deliberately called simulation_completed_unreviewed
with physical_fit_verified=false. Export/API success alone does not prove good
